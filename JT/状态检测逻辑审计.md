## 二、状态检测方式（两套系统）

### 系统A: 增强检测 (detectGameStateEnhanced → smartDetectState)
- 调用链: detectCurrentRuinsState → smartDetectState → detectStateWithRetry(3次) → detectGameStateEnhanced
- 流程: analyzeAllFeatures → calculateStateProbabilities → 取最高概率
- **问题**: 经常返回"未知"(100%置信度)，且置信度计算方式让"未知"容易胜出

**概率计算** (calculateStateProbabilities):
- 地图: 有节点+0.4, 黄色>5%+0.3
- 战斗: 有血条+0.5, 红色>10%+0.3
- 选择: 有卡片叠加+0.4, 橙色标题+0.3
- 胜利完成: 粉色标题+黄色按钮 → +0.6
- 节点挑战: 有挑战按钮+0.5, 有放弃按钮+0.2
- 商店: 绿色>3%+0.4
- 事件: 蓝色>3%+0.4
- 准备: 黄色按钮且无节点+0.3
- 入口界面: 黄色按钮且黄色<5%+0.2
- 未知: 基础0.1

### 系统B: 简单像素检测 (detectGameState)
- 作为增强检测返回"未知"时的兜底
- 优先级: 战斗(redRatio>0.15) > 失败 > 选择(3/5卡片列) > 准备(黄紫比例) > 弹窗(蓝灰+暗色) > 地图(黄色>2%) > 未知

## 三、智能探索入口流程

```
1. 检测当前状态 (detectCurrentRuinsState → 增强检测)
2. 如果"未知" → 简单像素检测兜底
3. 如果仍"未知" → 等待 → 再检测一次
4. 如果仍"未知" → 点击"前往遗迹"按钮
5. 进入 smartExploreRuins 循环
```

## 四、smartExploreRuins 主循环流程

```
每步:
1. capturePage → analyzeRuinsMap (检测节点+弹窗+状态)
2. 根据状态执行操作:
   - 地图+弹窗 → 点击挑战按钮
   - 地图+节点 → 选择最优节点 → 点击 → 可能弹出挑战
   - 地图+无节点 → consecutiveNoNodes++ → 达到3次则结束
   - 战斗 → handleBattle(15秒轮询)
   - 选择 → handleSelection (连续3次后点击确定退出)
   - 胜利完成 → handleVictoryComplete(使用victoryConfirmButton配置)
   - 商店 → closeShopIfPresent
   - 失败 → 点击(0.5, 0.85)
   - 事件 → handleEventSelection
   - 准备 → clickStartChallengeButton(使用nodeChallengeButton配置)
   - 未知 → 等待2秒
```

## 五、关键操作函数

| 函数 | 坐标来源 | 功能 |
|------|---------|------|
| clickGoToRuinsButton | ruinsConfig.goToRuinsButton | 点击前往遗迹 |
| clickStartChallengeButton | ruinsConfig.nodeChallengeButton | 点击挑战按钮(准备弹窗) |

| closeShopIfPresent | 检测+关闭 | 关闭商店 |
| handleEventSelection | 固定位置 | 选择第一个事件选项 |

## 六、当前已知问题

### 核心问题: 增强检测不准
1. 经常返回"未知"(100%置信度)
2. 基础未知概率0.1，但多特征不匹配时容易累计到最高
3. analyzeAllFeatures的子检测器阈值可能不匹配实际画面

### 选择/弹窗区分问题
4. detectSelectionState在弹窗/选择界面都返回"选择"（3/5卡片列）
5. 弹窗准备界面→应该走"准备"，但可能被识别为"选择"

### 操作函数问题
6. handleEquipmentSelection点击(0.2, 0.55)是硬编码，确认按钮(0.5, 0.78)也是硬编码
7. detectSelectionType区分英雄选择和装备选择靠蓝色标题栏，经常失败
8. 连续选择防护：超过3次点击确定按钮退出，可能误触发

### 配置问题
9. victoryConfirmButton已修复保存到config.json
10. 失败按钮坐标硬编码(0.5, 0.85)

## 七、建议改进方向

1. **简化状态检测**：增强检测系统过于复杂，简单像素检测反而更准确
2. **增加截图保存**：每次状态检测失败时保存截图，方便用千问VL校准
3. **可配置化**：更多硬编码坐标改为配置项
4. **失败重试**：操作失败后应增加重试或跳过机制
